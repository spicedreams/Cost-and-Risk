Done. I created a single self-contained Python script that matches the corrected specification and writes JSON plus CSV outputs when run.

Download:	generate_risk_pert_test_data.py

What the script does
It generates:

12 valid parent impact test sets
63 valid child estimates across those sets
standalone invalid child-estimate cases
beta-PERT alpha/beta parameters
parent P10/P50/P90 expected values
empirical tolerance bands using repeated simulations
JSON and CSV outputs

It uses:

NumPy and Pandas
numpy.random.RandomState, which uses MT19937 / Mersenne Twister
configurable lambda_value, defaulting to 4.0
10,000 samples per child by default
quick mode with 100 repeated reference runs
audit mode with 10,000 repeated reference runs

I also smoke-tested the script successfully with a reduced run count and sample count. The smoke test confirmed:

12 valid parent sets
63 valid child rows
12 invalid child cases
36 parent quantile expectation rows, covering P10, P50, and P90 for each parent
How to run it

Quick mode:
Shell
1	python generate_risk_pert_test_data.py --mode quick --output-dir generated
Show more lines

Audit mode:
Shell
1	python generate_risk_pert_test_data.py --mode audit --output-dir generated_audit

Override settings for testing:

Shell
1	python generate_risk_pert_test_data.py \
2		--mode quick \
3		--reference-runs 10 \
4		--samples-per-child 1000 \
5		--output-dir generated_test

Audit mode runtime

Audit mode is intentionally heavy: 10,000 repeated reference runs × 10,000 samples per child across 63 valid children. That is the right direction for a high-confidence tolerance fixture, but it may take a long time on a laptop. I included --reference-runs so you can do fast smoke tests before generating the authoritative audit outputs.
